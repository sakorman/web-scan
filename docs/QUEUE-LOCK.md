# 空闲队列避开数据库写锁

2026-11-13。空闲队列原本每半秒执行一次 `BEGIN IMMEDIATE`。即使没有重建任务，只要另一个连接持有写事务，队列就可能把服务的事件循环一起阻塞。现在先读队首，只有找到任务才尝试领取；其他连接正在写时，下次轮询再试。

## 锁竞争实测

在[原提交](https://github.com/sakorman/web-scan/commit/9f89684)与修改后分别启动真正的 Runner，每组使用独立的空 WAL 数据库。另一个线程申请写锁并按时释放，在服务的同一个事件循环安排一个 50 ms 定时器，记录它实际何时执行。

| 写锁持续 | 原定时器实耗 | 修改后实耗 |
| ---: | ---: | ---: |
| 1.2 秒 | 1.248 秒 | 0.050 秒 |
| 31 秒 | 31.057 秒 | 0.052 秒 |

四次测量中队列都存活。此结果说明原实现在写锁竞争下会拖延同一事件循环上的工作；未测 HTTP 吞吐或无锁时的延迟分布。实验没有锁定真实项目数据库，也不能解释[上次数据库无法打开](SERVICE-READINESS.md)的根因。

队首按创建时间排序，时间相同按插入顺序领取。读出候选后，更新时仍要求任务处于排队状态；只有成功更新并提交才启动进程。只对领取连接禁用锁等待，遇到 SQLite 的 BUSY 类返回码就保留任务，其他数据库错误继续暴露。维持单工作进程与原有轮询间隔：写锁释放后仍可能等到下一次轮询；长期写锁仍能延迟开工。此改动不涵盖启动恢复、上传或工作进程写报告的等待。

[OpenDroneMap 的 NodeODM 3.6.2（d45bc41，AGPL-3.0）](https://github.com/OpenDroneMap/NodeODM/blob/d45bc41b0c7a51e7f3796035f3bc238e9e01d0a2/libs/TaskManager.js#L194-L231)在加入或完成摄影测量任务时安排后续处理。这里保留 SQLite 持久队列和轮询，只采用“有任务才领取”的思路，没有引入其代码。读写并发和写事务行为见 [SQLite 事务说明](https://sqlite.org/lang_transaction.html)。Dahal、Abdelfattah、Rahimi 的[近期系统综述（2026-10，v1）](https://arxiv.org/abs/2610.17513v1)区分建模和渲染的性能口径；本实验测的是调度延迟，不能换算为训练或渲染提速。

## 两个实拍任务

通过 8787 服务串行提交。使用与前次相同的 ETH3D RGB 照片、共享 RADIAL 相机和缓存位姿，未用官方位姿、雷达或深度。输入 1600×1067，Brush 0.3.0 / Metal，种子 42、3,000 步、训练长边 512、高斯上限 150,000；训练期间未打开模型渲染。留出照片参与 SfM，但不参加高斯训练。读回两份完整 SH3 PLY 并核验全部评估图摘要。所有视图的内外参、画幅、去畸变图相对位置和留出参考摘要与基线相同。

| 场景 | 定位/输入；训练/留出 | 高斯数 / PLY 字节 | 位姿缓存恢复 / 训练评估导出 / 工作进程总时长 / 入队至成功（秒） |
| --- | --- | ---: | ---: |
| pipes | 14/14；12/2 | 11,676 / 2,757,086 | 0.0294 / 22.7978 / 22.87 / 23.1144 |
| office | 26/26；22/4 | 14,434 / 3,407,974 | 0.0342 / 23.6284 / 23.71 / 24.0900 |

两组均无失败视角。首次核对 pipes 时，逐字比较场景 JSON 因新任务图片路径带有不同任务编号而失败；只去掉各自的任务根目录后重新比较，其余字段全等，未重复训练。计时不含照片准备和上传，不是冷启动。结果不涉及 CUDA。

```sh
mkdir -p .data/benchmarks/queue-lock
PYTHONPATH=. .venv/bin/python docs/benchmarks/queue-lock-probe.py .data/benchmarks/queue-lock
.venv/bin/python -m pytest -q tests/test_queue_claim.py
```

新增回归覆盖写锁期间保留任务、释放后恢复、队首顺序、读出候选后发生取消，以及非竞争错误传播。全量 298 项后端、18 项前端、类型检查与生产构建通过。后续若有排队迟迟不开工，再区分持锁时长和工作进程状态；若 pipes 在同一口径下持续下降，再做多次配对训练。
