# 评分不再隐式放大渲染图

2026-10-26。原对照脚本只按请求尺寸缩放参考照片，再将两张渲染图调整到同样大小。当渲染只有128像素、请求评分长边为512时，图像会被放大四倍后计算PSNR、SSIM和LPIPS。新流程将评分上限限制在两组所有留出图实际共有的分辨率内，并记录每个视角的原生与评分尺寸。

这是评分规范的修正，没有改变训练器或模型。此前放大后得到的数值仍是那种处理方式的结果，不能与新的原生尺寸成绩直接混算；历史JSON保持原样。

## 实际行为

同一组原生128×84的pipes渲染，调用 `--size 512`：

| 评分口径 | 实际尺寸 | 参数求导模型：PSNR / SSIM / LPIPS | 参数冻结模型：PSNR / SSIM / LPIPS |
| --- | --- | --- | --- |
| 修改前 | 512×336 | 16.4917 / 0.62978 / 0.60159 | 17.2252 / 0.63429 / 0.60251 |
| 修改后 | 128×84 | 16.9302 / 0.59794 / 0.42616 | 17.7523 / 0.59270 / 0.44169 |

这些是同两个已保存模型、同两张留出照片的均值，文件完全没变。分数变化由评分尺度引起，不是重建效果提升。新PSNR / SSIM与[冻结参数实验](LPIPS-FROZEN.md)此前明确按128尺寸计算的结果一致。

同时复查两组原本已经满足512像素评分条件的pipes / office模型：处理后的RGB图片摘要、PSNR、SSIM和LPIPS均保持一致。每组默认损失与LPIPS模型的比较仍沿用[原记录](PERCEPTUAL-EVAL.md)，不改变此前结论。

## 尺寸规则

先完成原有的相机、留出拆分、图片集合和摘要检查，再从两组全部渲染PNG中取共同长边上限。参考图保持原画幅，用Lanczos缩小到这个上限；若渲染器短边舍入比参考图少一个像素，再收紧宽高边界，保证参考图和两个渲染在任一方向都不会被放大。

旧报告没有 `resolution` 时，检查全部渲染图恢复上限。第一张照片可能本来较小，不能把它的尺寸当作整组训练分辨率。尺寸不足以计算SSIM或LPIPS时明确报错，不为满足评分器要求而放大。

报告新增：

| 字段 | 含义 |
| --- | --- |
| `requested_comparison_size` | 调用者请求的长边上限 |
| `comparison_size` | 请求与两组原生渲染共同允许的上限 |
| `scoring_dimensions` | 每个视角的实际宽高及两边、参考图的原生宽高 |
| `resize_policy` / `resampling` | `never_upscale` / `Lanczos` |

短边舍入可能让某张图的实际长边略小于上限，逐视角尺寸是最终依据。PSNR / SSIM与LPIPS继续使用同一份RGB像素。

## 验证范围

新增9项回归：两边不同分辨率、横图、竖图、显式缩小、短边舍入、单张小图限制整组、旧报告及首张较小的旧报告、尺寸不足时的清晰错误。最初5项检查先在旧实现上失败，修复后全部通过。136项后端、18项前端、类型检查和构建通过。

实际验证使用6个已完成的500步照片模型，分别是128像素pipes对照，以及512像素pipes / office对照。每组相机与留出参考一致；pipes 14/14定位、12训练/2留出，office 26/26定位、22训练/4留出，没有失败视角。模型原步数、点数、PLY大小、引擎及耗时均随[公开数据](benchmarks/scoring-size.json)保留，142个原文件前后摘要一致。

本轮不需要新增重建、SfM或训练测速，直接用真实重建输出验证评分变化。不同评分尺寸的计算成本也不作为算法提速。图片引用原生128像素文件，不做放大对比图，避免让显示插值与实际模型细节混淆。

## 使用与限制

命令不变，`--size` 现在明确表示请求上限。例如128像素结果即使请求512，也会报告请求512、有效128及128×84的实际网格：

```bash
.venv/bin/python scripts/compare_quality.py \
  --data .data/benchmarks/lpips-frozen-20261026 \
  --quick pipes-128-0-baseline --detail pipes-128-0-candidate --size 512 \
  --lpips-scorer .data/benchmarks/perceptual-eval-20261026/lpips_score \
  --output .qa/native-comparison.json
```

基线提交[9a20934](https://github.com/sakorman/web-scan/commit/9a20934)。[3DGS公开评测代码](https://github.com/graphdeco-inria/gaussian-splatting/blob/main/metrics.py)配对渲染与参考RGB图逐视角评分，[LPIPS实现](https://github.com/richzhang/PerceptualSimilarity)明确网络与输入规范；本项目不放大原生渲染的规则是本地评测选择，不是从这些项目移植的强制协议。未复制外部实现代码。

这项修复不解决采集覆盖或几何缺失，也不新增画质收益。后续比较应固定有效评分尺寸和指标身份，不能将历史放大口径的成绩直接并入新基线。图片和数据沿用ETH3D署名及CC BY-NC-SA 4.0许可。
