# 导入与重复重建

这次主要处理两个实际等待点：上传一张才能处理下一张，以及调整训练参数时重复求相机位姿。

## 初始点筛选的体积与质量取舍 · 2026-10-31

冻结两组场景，每种设置重复两次；最短轨迹从 2 提到 3 后，pipes / office 的完整 PLY 均值从 2,680,504 / 3,429,450 字节降至 1,960,113 / 2,762,042 字节，但 office 两次 SSIM 回退，未采用。训练、评测与导出计时均值差为 -0.5126 / -1.0130 秒，计时有一秒轮询粒度且高斯数改变，不能宣称等质量提速。本轮复用准备好的 SfM，未测 SfM、端到端或训练峰值内存。[逐次数据与范围](TRACK-INITIALIZATION.md)

## 图片与视频导入

浏览器现在允许最多 3 个上传请求同时执行。图片或视频帧先写入 IndexedDB，再进入有界队列；队列满了会暂停生产下一帧。这样视频解码可以和网络上传重叠，待传缓存仍受 20 张 / 64 MB 上限约束。

请求失败时，等待已发出的请求结束，保留没有成功确认的可恢复帧。完成导入或冻结输入之前，必须等上传队列排空。

同一批导入会记录批次和帧序号，服务端按采集顺序返回照片、冻结清单。并发完成的先后顺序不会变成训练照片的顺序。历史照片没有这些字段时仍使用原来的顺序。

源图可到 4800 万像素，但压缩文件上限仍是 16 MiB；服务端在完整解码前检查尺寸，随后统一缩到 2400 像素长边。30MP 合成边界图的完整接口检查为 0.1616 秒，只用来验证安全路径，不代表手机上传或公网吞吐。两组 ETH3D 普通 1600×1067 输入的完整重建回归见 [高像素照片归一化](HIGHRES-INGEST.md)。

## 相机结果复用

同一个已冻结的采集，再次训练时可以复用相机、稀疏几何和去畸变照片。缓存键包含有序图像清单、图像摘要、尺寸、COLMAP / NumPy 版本和相关求解代码摘要。训练步数等只影响训练的参数不参与这个键。

每次运行仍校验原始照片。缓存有完整文件清单、大小和 SHA-256；缺失、损坏或版本不匹配时重新求解。缓存全部写完后才发布，恢复到新任务目录时复制文件并重定位图像路径，训练不会修改共享缓存。

目录位于 `.data/sessions/<id>/cache/sfm/<key>/`，由当前单 Worker 管理。只有完整成功的 SfM 结果可复用；不是训练检查点续跑，也不保证不同输入可以共用。

2026-10-30 起，场景快照也保留原始相机内参，任务另存冻结照片清单；缓存任务可直接校验采集原图做原始域评测，无需复制原始照片或完整稀疏模型。代码摘要变化会使升级后的首次重建重新求解，旧缓存与历史结果仍保留。[开销、实测与限制](RAW-CACHE-EVALUATION.md)

## 实测

Apple Silicon macOS，同一组 26 张办公室照片，Brush 0.3.0，1000 步，512 像素长边，5 万高斯上限。连续两次运行相同参数：

| 阶段 | 首次计算 | 复用结果 |
| --- | ---: | ---: |
| 输入校验 | 0.0081 s | 0.0032 s |
| SfM / 缓存恢复 | 8.6013 s | 0.0342 s |
| 保存缓存 | 0.0410 s | — |
| 训练及模型导出 | 8.0741 s | 7.0515 s |
| 总任务时间 | **16.76 s** | **7.12 s** |

两次都注册了 26 张照片，相机归一化结果一致。总任务时间减少约 57.5%；主要收益来自省掉重复 SfM，训练耗时也有运行波动，不能将全部差异都归因于缓存。

这组数据用于验证重用行为，不是所有场景的速度承诺。首次重建仍完整执行 COLMAP；此次实验未修改训练画质参数。并发上传通过队列测试和浏览器 MP4 导入验证，没有拿本机网络测试推断公网倍速。

## 复现

先新建采集，导入并冻结同一组照片，再运行：

```bash
.venv/bin/python scripts/benchmark_reuse.py --session <采集ID>
```

脚本提交两次相同的本地 GPU 任务，将完整报告写入 `.qa/reuse-benchmark.json`。如果该采集已存在有效缓存，第一次也可能命中；脚本会明确提示，不把两次命中当成冷 / 热对比。

报告新增 `sfm_reused`、`sfm_cache_key` 和 `timings`。`sfm_seconds` 包含缓存检查与恢复，或输入复制与完整求解；`training_and_model_export_seconds` 包含训练后端及其模型导出。总时间还包含其他初始化和汇总开销。

## 检查

- 单测覆盖缓存损坏、半成品、版本与图像变化、顺序变化、恢复路径和原图校验。
- 并发队列验证最多 3 个请求、队列背压、在途失败与完成等待。
- 服务端测试用乱序到达的 12 帧核对预览与冻结清单仍按原始序号排列。
- 浏览器导入 12 秒 MP4，得到 12 张照片，帧序号与时间均保持 0–11 的顺序。

## 训练导出

2026-10-30，PLY 有限值检查改为按连续记录分块扫描，临时布尔数组最多 1 MiB。基于已包含直接写数组的版本，两个历史大模型各三次交错测量，完整转换中位数由 97.312 / 65.909 ms 降至 51.922 / 40.863 ms，峰值 RSS 基本不变，文件逐字节一致。收益仅为转换阶段，未证明训练或端到端提速。[完整数据与回归](PLY-VALIDATION-SCAN.md)

2026-10-30，PLY / splat 直接写数组以减少临时副本。真实 30 万 / 23.14 万高斯模型各三次交错测量，独立转换进程峰值 RSS 中位数分别减少 76.86 / 59.19 MiB；全部输出逐字节一致。转换耗时仅少约 12 / 16 毫秒，不能写作整条重建流程提速。[测量范围、复现和完整回归](EXPORT-MEMORY.md)

训练进度已改为读取 Brush 的实际 refinement 日志，每轮轮询最多读取 64 KiB；不再依赖中间 PLY 来驱动进度条。训练器仍每 500 步导出一次；最终模型通过目标步数、完整顶点数据和必要数值检查，并完成转换后，才清理这次任务的较早 PLY。以前的任务不会被批量清理。

模型报告新增 `export_policy`、`export_written_files`、`export_written_bytes`、`export_files`、`export_bytes`、`export_removed_bytes`、`export_cleanup_errors`、`training_process_seconds` 与 `progress_source`。其中 `export_written_bytes` 是训练器写出的 PLY 总量，`export_bytes` 是清理后留存量，不含评估图、下载用的规范化 PLY、splat 或 SfM 缓存。实测结果见 [迭代记录](ITERATIONS.md)。


## 重复对照

`scripts/benchmark_exports.py` 可用 `--repeats 2 --resolution 512` 重复比较候选适配器。每组输入固定，顺序交错，启动前保存适配器源码快照；汇总展示每种设置的均值及范围。汇总前会锁定所有留出照片的文件名、参考图摘要和画幅，防止数量相同但评测对象不同的结果混入同一对照。一次或两次运行仍不足以建立一般性能结论。默认参数保持原有行为，增点策略的实际对照见 [REFINEMENT.md](REFINEMENT.md)，身份检查的控制实验见 [BENCHMARK-IDENTITY.md](BENCHMARK-IDENTITY.md)。

每个导出基准现在同时写出 `sfm/scene.json`、相机和报告工件，因此可直接交给 `compare_quality.py` 复核相机与留出照片后评分。200 步间隔筛查只少用约 4% 时间，却因显著减少高斯而在两组场景降低 PSNR / SSIM，不作为同画质提速。[完整口径与原始汇总](REFINEMENT-200.md)

高梯度扩张比例从 `0.1` 到 `0.2` 使两组模型分别增加 365.32% / 278.26% 的高斯，训练、评测与导出各慢约 21.7%，且共同网格 PSNR 均下降；没有用更多高斯冒充质量或性能优化。[测量口径与限制](GROWTH-SELECT.md)

均值噪声从 `40` 到 `20` 的 pipes / office 串行筛查分别为 23.3030 → 23.2823 s、23.2953 → 23.2973 s；候选高斯仅少 0.42% / 1.95%，差异处于单次测量范围，不能写作提速或压缩收益。office 的共同网格分数也回退，默认保持不变。[测量口径与限制](MEAN-NOISE.md)
