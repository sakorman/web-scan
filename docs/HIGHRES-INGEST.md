# 高像素照片归一化

2026-10-27。手机照片会在进入 SfM 前统一为 JPEG 和有限的长边尺寸。此前服务端在 2400 万像素处直接拒绝原图，而后续流程本来就会缩小图片；现在把安全输入上限提高到 4800 万像素，超出后仍在解码像素前拒绝。

## 处理边界

- 压缩文件上限仍为 16 MiB，单项目仍为 200 张 / 512 MiB；这次不放宽网络和磁盘容量边界。
- 允许的源图不超过 48,000,000 像素。Pillow 的炸弹图保护保持启用；48MP 到其二倍阈值之间的警告只用于让服务返回统一的 48MP 错误，尺寸检查发生在完整解码、旋转和缩放之前。
- EXIF 方向先校正，再以 Lanczos 限制到 2400 像素长边，输出 JPEG quality 94。有效的 35mm 等效焦距仍写回最小 EXIF 块；COLMAP 以归一化后的对角线换算像素焦距，缩放不会沿用错误的像素焦距。
- 每张照片的 `metadata.normalization` 保存源尺寸、像素数、最终尺寸和是否缩放，方便在项目内追溯输入变化。原始压缩照片不落盘。

## 边界检查

本机用一张合成的 6000×5000（3000 万像素）JPEG 走完整上传接口。它不是画质或速度基准，只检验导入边界：470,184 B 输入被规范化为 2400×2000、75,684 B 的 JPEG，35mm 等效焦距 28 仍可读取；单次 TestClient 请求为 0.1616 秒。单元测试另以缩小后的阈值覆盖缩放、元数据写入及超限拒绝，避免常规测试分配大图。

随后重新导入 ETH3D 的两组实拍并串行完成 3,000 步 / 512 像素 / 15 万高斯预算的共享内参 Brush 任务。样本输入本来就是 1600×1067，因此不会缩放；目的是确认导入记录没有改变普通重建链路，而不是把两次随机训练当作质量对照。

| 场景 | 输入 / 定位 | 训练 / 留出视图 | 高斯 / PLY | 留出 PSNR / SSIM | SfM / 训练导出 / 全程 |
| --- | ---: | ---: | ---: | ---: | ---: |
| ETH3D pipes | 14 / 14 | 12 / 2 | 10,903 / 2,574,658 B | 18.793522 / 0.760213 | 5.8022 / 23.2572 / 29.13 s |
| ETH3D office | 26 / 26 | 22 / 4 | 14,323 / 3,381,778 B | 21.803417 / 0.87744385 | 8.4836 / 23.2779 / 31.84 s |

两组评测均在 512 像素长边输出；留出照片参与了上游 SfM，不是独立端到端指标。两次任务均通过完整 SH3、相机、留出图片和下载 PLY 校验。Brush 的训练并不保证确定性，以上数值不能与旧任务直接相减后宣称画质或速度提升。pipes 仍有 1 个、office 仍有 5 个相对稀疏支撑较低的已定位视角，详见 [稀疏视角诊断](SPARSE-COVERAGE.md)。完整机器可读结果在 [highres-ingest.json](benchmarks/highres-ingest.json)。

## 限制与下一步

4800 万像素是解码安全与移动端常见高分辨率的折中，并不表示更高像素必然带来更好的位姿或几何；模糊、反光、覆盖不足和混合镜头仍会影响结果。48MP 的实际手机照片还需要在不同编码、方向和内存条件下补充测试。若增加原图保留或提高网络容量，应单独评估本地磁盘、上传恢复和隐私边界，不能与本次归一化混为一项优化。
